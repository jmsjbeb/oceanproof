## 为什么要做这个工具

2023 年 8 月起，福岛第一核电站以约 30 年的排期将ALPS 处理水排入太平洋。面临这个问题的是两类完全不同的人：

- **沿海渔民**（浙江、福建、山东）——订单被禁运和消费者回避直接冲掉。一份"安全"的检测结论救不了他们，因为市场读的是新闻，不是剂量。
- **内陆消费者**（成都、西安）——承担同样的声誉成本，却没有任何办法去核实顾客转述的那个"水"的故事。

目前没有任何工具给这两类人一个**落到具体地点、可核验**的回答。更糟的是，公共讨论把"可忽略的辐射风险"和"彻底的生计冲击"混成一件事——这个方向恰好是反的。

## 核心设计：两本账，从不混算

| | 辐射账本 | 生计账本 |
|---|---|---|
| **结论** | 比 WHO 饮用水导则低约 6 个数量级 | 压力指数 78/100 |
| **刻度** | 对数 | 线性 |
| **单位** | 毫希沃特（总通路剂量） | 无量纲指数 |
| **含义** | 物理量 | 由公开贸易/价格信号构造的信号 |
| **配色** | 紫 `#C084FC` | 青 `#2FE3C0` |

两本账并排呈现，**绝不合并成一个风险分**——剂量和生计损失不可通约，压在一起就是撒谎。

> **渔民失去的是订单，不是剂量。** 两句话必须一起说，只说一句都没用。

## 工作原理

1. **先算物理输运。** 拉格朗日粒子追踪（海洋 6 万粒子 / 大气 60 万粒子），由 NOAA CoastWatch 0.25° 实测表层洋流与 NCEP/NCAR 再分析风场驱动。没有模型去"猜"水往哪走。
2. **再算剂量通路。** 浓度场接入食物链模型（水→藻类→鱼），按对数刻度以毫希沃特报告，使用 IAEA TRS-472 浓度因子与 ICRP 72 剂量系数。
3. **最后给账本。** 辐射结论与生计指数并排，不合并。

覆盖范围：**65 个精细沿海点位** + 全国 **3237 个行政区**，支持中文名搜索。

## 关于不确定性的诚实

标定常数本身只有**量级**意义。因此：

- 所有数字按**量级区间**呈现，不给小数点后多位
- 每个值带**来源等级标签**：实测／模型／估算／示意
- 每一页都印着边界：**筛查级工具，不是预警系统，不是监测站**

### AI 刻意不做的事

- **不模拟监测数据。** 中国沿海氚监测未开放为 API，我们不伪造数据源。
- **不给七位数的假精度。** ~1 个数量级的不确定度撑不住。
- **不生成统一风险分。** 见上。
- **不做政治表态。** 只谈物理输运、剂量物理学与市场观察。

## 数据时效

站点是**快照，不是实时流**。运行时零网络请求：所有场在构建阶段算好、以 `.js` 形式随页面下发，所以断网也能跑。

由此有两个后果，界面里都写着：

- **抵达天数不会一天一变。** 它来自三条标定输运路径（锚点：中国沿岸 240 天 / 北美西岸 1200 天），不是今天的流场。时间锚点（距 2023-08-24 多少天）在浏览器里算，界面会自己从「预计 N 天后抵达」翻成「已进入影响窗口 N 天」。
- **会变旧的是三样**：批发价、洋流场、排放轮次。站内「数据时效」页逐项列出日期、更新频率和生成脚本，过期的自己变琥珀色、再变紫色。

`tools/` 里是完整的取数与构建流程。一条命令刷新：

```bash
python tools/refresh.py          # 价格 + 流场 + 清单 + 单文件
```

每一步独立失败：某个源抓不到，就保留上一份，站点照常运行。

## 技术实现

零依赖、零构建的纯静态站点。原生 JS + CSS，无框架、无打包器、无外部 CDN——`file://` 直接打开和部署到 GitHub Pages 表现完全一致。

## 本地运行

```bash
python -m http.server 8000
# → http://localhost:8000
```
